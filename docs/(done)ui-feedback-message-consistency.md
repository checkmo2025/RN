# UI 피드백 문구 통일 가이드 (9번 항목)

> 기준 문서: `docs/(done)ui-consistency-top10.md`의 9번 항목  
> 범위: RN `src/**/*.tsx`, `src/services/api/http.ts`, `src/utils/toast.ts`

## 1) 점검 목적
- 성공/실패/빈 상태/진행 상태 문구 톤을 통일한다.
- 토스트/알럿 사용 기준을 정리해 사용자 피로도를 줄인다.

## 2) 현재 현황 요약 (RN 기준)
- `showToast()` 호출: 322건
- `Alert.alert()` 호출: 19건
- 토스트 집중 파일:
  - `MeetingScreen`: 129
  - `MyPageScreen`: 61
  - `AuthFlowScreen`: 48
  - `StoryScreen`: 35
- 에러 메시지 resolver 함수는 일부 화면에 존재하나(`resolve*ErrorMessage`) 전체 공통은 아님

## 3) 통일 정책 (초안)

### A. 피드백 채널 규칙
- `Toast`: 비차단 정보/완료/경미한 오류
- `Alert`: 파괴적 액션 확인, 되돌리기 어려운 결정
- `Inline`: 빈 상태/입력 검증/로딩 안내

### B. 문구 톤 규칙
- 동작형: `~ 중...`
- 성공형: `~했습니다.`
- 실패형: `~에 실패했습니다.`
- 빈 상태: `~이 없습니다.` / `~를 찾을 수 없습니다.`

### C. 중복/과다 노출 방지
- 같은 요청 실패를 연속 토스트로 반복 노출하지 않도록 가드
- 동일 화면에서 토스트/알럿/인라인 피드백 역할 중복 금지

### D. 에러 매핑 규칙
- HTTP 상태 코드별 공통 기본 문구 사전 유지
- 화면별 resolver는 공통 사전 위에서 덮어쓰는 방식으로 단순화

## 4) 1차 정리 대상
- 토스트 과밀 구간(`MeetingScreen`)부터 액션별 메시지 템플릿 정리
- `Alert.alert` 문구 형식과 버튼 레이블 통일
- `ui-copy` 기준(`중/중...` 띄어쓰기) 반영

## 5) 2차 정리 대상
- `feedbackMessageMap` 공용 상수화 검토
- 성공/실패 이벤트의 문구 키 기반 호출로 전환
- 빈 상태 컴포넌트(아이콘+문구) 공통화

## 6) 완료 조건
- 화면별 피드백 톤과 형식이 일관됨
- 동일 상황에서 피드백 채널 선택 기준이 명확함
- 중복 토스트/과도한 알럿 사용이 줄어듦
