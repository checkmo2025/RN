# Fetch 점검 이슈 정리 (회원 / 책이야기 / 소식)

- 작성일: 2026-04-27
- 범위: 관리자 API 제외, 앱에서 실제 사용하는 조회/관련 fetch 흐름
- 기준: Swagger(`https://api.checkmo.co.kr/swagger-ui/index.html#/`) + OpenAPI + RN 코드 + 일부 실서버 응답 샘플

## 판정 기준

- `RN`: 프론트 구현/UX/에러처리/페이징 반영 문제
- `BE`: 서버 동작/응답 형식/권한 정책 문제
- `BE 문서`: 서버는 동작하지만 Swagger 문서와 실제가 불일치
- `공동`: 양쪽 합의 후 함께 정리해야 하는 항목

## 회원 영역

- `[MEM-01] 내 신고내역 날짜 필드 불일치`
- 판정: `RN`
- 내용: `/members/me/reports` 스키마는 `reportDate` 중심인데 앱은 `createdAt` 기준으로 표시함.
- 방향: 앱 매핑에서 `reportDate` 우선 처리, 하위 호환으로 `createdAt` 보조 처리.

- `[MEM-02] 내 신고내역 페이징 미반영`
- 판정: `RN`
- 내용: API는 `hasNext/nextCursor`를 제공하지만 화면에서는 단건 조회 성격으로 사용 중.
- 방향: 커서 루프를 공통화해서 신고내역도 끝 페이지까지 수집.

- `[MEM-03] 일반 회원 플로우에 관리자 API fallback 잔존`
- 판정: `RN`
- 내용: `/members/me/reports` 실패 시 `/admin/.../reports` 호출 시도 로직이 남아 있음.
- 방향: 일반 사용자 경로에서 관리자 fallback 제거, 실패 시 사용자 메시지/재시도 정책으로 통일.

- `[MEM-04] find-email GET fallback`
- 판정: `공동` (우선 `BE 문서` + `RN 정리`)
- 내용: 문서는 POST만 정의되어 있는데 앱에 GET fallback이 남아 있음.
- 방향: 서버 정책을 하나로 확정(POST only 권장)하고 문서/서버/앱 fallback 정리.

- `[MEM-05] 닉네임 사전검증 규칙 약함`
- 판정: `RN`
- 내용: 길이 검증 위주라 서버 패턴 오류를 클라이언트에서 미리 걸러내지 못함.
- 방향: 서버 패턴/길이 규칙을 클라이언트 동일 규칙으로 선검증.

## 책이야기 영역

- `[BOOK-01] 수정 화면 UX와 서버 수정 가능 범위 불일치`
- 판정: `RN`
- 내용: 수정 화면에서 제목/책 변경이 가능한 것처럼 보이지만 실제 update 요청은 `description`만 반영.
- 방향: 수정 모드에서 제목/책 선택 비활성화 또는 "본문만 수정 가능" 명시.

- `[BOOK-02] 일부 화면에서 책이야기 페이징 미반영`
- 판정: `RN`
- 내용: 내 프로필/다른 사람 프로필은 커서 반복 없이 첫 페이지만 사용.
- 방향: Story 메인과 동일한 커서 루프 적용, 공통 fetch 유틸 재사용.

- `[BOOK-03] 피드 조회 실패가 무음 처리되는 구간 존재`
- 판정: `RN`
- 내용: 일부 ApiError가 사용자에게 안내되지 않아 실패 원인 파악이 어려움.
- 방향: 조회 실패 UX 정책을 통일(401/403/404/5xx별 메시지 최소 기준 정의).

- `[BOOK-04] 공개/인증 필요 여부 문서와 실제 차이`
- 판정: `BE 문서`
- 내용: 일부 엔드포인트(`all/member/search`)는 익명 200인데 문서는 401 응답이 함께 기술되어 혼동 가능.
- 방향: 실제 권한 정책 기준으로 Swagger 응답/설명 업데이트.

- `[BOOK-05] 날짜 형식 표기 차이`
- 판정: `BE 문서`
- 내용: 스키마는 `date-time`인데 실제는 `YYYY-MM-DD HH:mm` 형태 응답이 존재.
- 방향: RFC3339로 통일하거나, 현재 포맷을 문서에 명확히 명시.

## 소식 영역

- `[NEWS-01] fetchNewsList에서 페이징 메타 유실`
- 판정: `RN`
- 내용: 서비스 함수가 목록 배열만 반환해서 `hasNext/nextCursor` 정보를 상위 화면이 못 씀.
- 방향: `fetchNewsList` 반환 타입을 목록+커서 메타 구조로 정리.

- `[NEWS-02] News/Home 목록이 구조적으로 1페이지만 사용`
- 판정: `RN`
- 내용: 서비스 반환 타입 한계로 추가 페이지를 가져오지 못함.
- 방향: `NewsScreen`, `HomeScreen` 모두 커서 기반 누적 로딩 지원.

- `[NEWS-03] 소식 상세/목록 ApiError 무음 처리`
- 판정: `RN`
- 내용: `ApiError`는 토스트 없이 빠지는 구간이 있어 실패 체감이 약함.
- 방향: 상세 진입 실패 시 사용자 안내 문구/복귀 동작 표준화.

- `[NEWS-04] 소식 조회 권한 문서-실서버 불일치`
- 판정: `BE 문서`
- 내용: `/news`, `/news/{id}`는 익명 조회 가능(실서버)인데 문서엔 401 케이스가 혼재.
- 방향: 공개 API 여부를 문서에 명확히 고정하고 응답 케이스 정리.

- `[NEWS-05] 미사용 fetch 함수 잔존`
- 판정: `RN`
- 내용: `fetchNewsCarousel`은 현재 호출처 없음.
- 방향: 제거 또는 실제 사용처 연결 중 하나로 정리.
