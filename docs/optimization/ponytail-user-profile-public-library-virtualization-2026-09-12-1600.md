## 2. 변경 전

바깥 `FlatList`는 책 이야기만 가상화한다. 공개 서재는 헤더 안의 `books.map()`에서 모든 카드를 즉시 생성한다.

```tsx
const renderLibraryCards = () => (
  <View style={[styles.gridContent, styles.bookWrap]}>
    {/* 기존 로딩·빈 결과 */}
    {books.map((book) => (
      <Pressable key={book.id} onPress={() => handleOpenBookSearchDetail(book)}>
        {/* 기존 표지·배지·제목·저자 */}
      </Pressable>
    ))}
  </View>
);
<FlatList data={showStoryRows ? storyRows : []} />
```

## 3. 가설·근거·기대 결과

### 가설

책을 3권씩 행으로 묶어 기존 바깥 `FlatList`에 전달하면, 긴 서재에서도 화면 주변 행부터 생성할 수 있다.
API·데이터·카드 JSX·상세 핸들러를 유지하면 사용자가 보는 데이터와 동작은 같을 것이다.

### 근거

- 공개 서재 전체 조회 결과를 헤더에서 바로 `map()`하고 있어 기존 가상화의 대상이 아니다.
- 같은 화면의 책 이야기와 마이페이지 서재에 행 가상화 패턴이 이미 있다.
- 기존 React Native `FlatList`를 재사용하면 새로운 라이브러리나 중첩 스크롤이 필요 없다.
- 앞선 측정에서 작은 목록의 가상화 고정비가 확인됐으므로 이번에도 무조건적인 속도 개선을 가정하지 않는다.

## 4. 변경 후

```tsx
const bookRows = useMemo(
  () =>
    Array.from({ length: Math.ceil(books.length / 3) }, (_, index) =>
      books.slice(index * 3, index * 3 + 3),
    ),
  [books],
);
const showBookRows =
  activeTab === '서재' && books.length > 0 && (!profileLoading || refreshing);
const showGridStatus = !showStoryRows && (!showBookRows || loadingBooks);

<FlatList<StoryCard[] | BookCard[]>
  data={showStoryRows ? storyRows : showBookRows ? bookRows : []}
  keyExtractor={(row) => `${showBookRows ? 'book' : 'story'}-row-${row[0]?.id}`}
  renderItem={(info) =>
    activeTab === '서재'
      ? renderBookRow(info as ListRenderItemInfo<BookCard[]>)
      : renderStoryRow(info as ListRenderItemInfo<StoryCard[]>)
  }
/>
```

- `renderLibraryStatus()`는 스켈레톤·빈 문구만 헤더에 렌더링한다.
- `renderBookRow()`는 기존 카드 JSX와 `handleOpenBookSearchDetail()` 연결을 그대로 사용한다.
- `loadingBooks`가 참이어도 기존 책이 있으면 목록 데이터를 유지한다. 초기 프로필 로딩이 끝나지 않았고 새로고침 중도 아니면 기존처럼 프로필 스켈레톤이 우선한다.
- 기존 책 이야기 행의 스타일 이름을 `gridListRow`로 일반화해 간격을 재사용했다.
- 책과 책 이야기 행의 키 접두사를 구분해 탭 전환 시 서로 다른 데이터를 같은 행으로 취급하지 않는다.
