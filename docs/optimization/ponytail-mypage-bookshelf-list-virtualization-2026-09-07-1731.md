## 3. 가설·근거·기대 결과

### 가설

기존 3열 책 배열을 세 권씩 행으로 묶어 이미 존재하는 바깥 `FlatList`에 전달하면 화면 주변 행부터
생성된다. 긴 서재의 첫 커밋 시간과 긴 프레임은 감소하고, 같은 `books` 순서와 기존 카드
JSX·좋아요 핸들러를 그대로 사용하므로 사용자 동작은 유지될 것이다.

### 근거

- `fetchAllMyLikedBooks()` 결과는 한 배열에 모두 저장되며 기존 `books.map()`은 화면 밖 카드까지 즉시 React 자식으로 만들었다.
- 각 카드에는 2:3 표지 이미지와 텍스트가 있어 단순 행보다 누적 렌더 비용이 크다.
- 인접한 원소 세 개를 한 행으로 묶으면 기존 3열 순서를 바꾸지 않고 바깥 세로 목록 하나로 가상화할 수 있다.
- 기존 바깥 `FlatList`를 재사용하므로 중첩 가상 목록과 새 패키지가 필요 없다.
- 조회·매핑·좋아요 상태 처리는 렌더 코드와 분리돼 있어 데이터 로직을 수정하지 않아도 된다.

마이페이지 `내 서재`의 3열 책 카드를 행 단위로 묶어 기존 바깥 `FlatList`의 가상화 대상으로
옮겼다. 데이터·표시 순서·문구·좋아요 동작과 로딩·빈 상태는 유지했고 핵심 변경은 98줄로 200줄
예산의 49.0%이며 새 의존성은 없다. Release 실험에서 100·500개 첫 커밋은 각각 54.6%, 90.2%
단축되고 긴 프레임이 제거됐지만, 실제 15권에 가까운 19개는 7.0% 느려 현재 응답속도가 개선됐다고
볼 수 없다. 따라서 이번 변경은 큰 서재에서 표지 카드 렌더 부하를 제한하는 확장성 개선이며 가설은
목록 규모에 따라 부분 확인으로 판정한다.

### 후속 작업

실기기에서 원격 표지 이미지 캐시가 비어 있는 상태와 채워진 상태를 나눠 마이페이지 진입부터 첫
조작 가능 시점까지 측정하면 실제 이미지 요청·디코딩 비용을 포함한 체감 성능을 보완할 수 있다.
