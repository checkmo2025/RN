### 범위와 사용자 동작 계약

ISBN 기반 모임·책이야기·좋아요 연결을 유지한다. 기존 표지 URL을 덮어쓰지 않는다. 추천의 목록/요일 정책은 서버가 담당한다. 공급자 상세 링크가 없으면 외부 이동을 제공하지 않는다. 빈 페이지라도 hasNext=true이면 사용자가 다음 결과를 요청할 수 있다.

## 2. 변경 전

알라딘 랭킹 링크가 남아 있었다. RN은 서버 상품 링크를 버리고 알라딘 홈으로 이동했다. 웹 이미지 허용 목록에는 예스24가 없었다. 일부 빈 검색 화면은 다음 페이지 접근을 막았다.

## 3. 가설·근거·기대 결과

기존 API 응답의 link와 hasNext를 사용하고 이미지 호스트를 추가하면 서버 DTO/ISBN 변경 없이 전환할 수 있다. 새로운 캐시나 외부 라이브러리는 필요하지 않다. 성능 향상이 아니라 응답/탐색 계약 보존이 성공 기준이다.

## 4. 변경 후

- 추천 링크를 [예스24 국내도서 종합 베스트셀러](https://www.yes24.com/Product/Category/BestSeller?categoryNumber=001)로 변경했다. 공식 페이지 접근을 확인했다.
- RN: link 정규화 및 null fallback, 헤더/책이야기/모임 책 선택의 빈 페이지 다음 버튼, 번역 추가.
- FE: 예스24 이미지 호스트 추가(알라딘 유지), nullable link/currentPage 계약, 링크 없는 카드 이동 제거, 헤더 빈 페이지 다음 버튼.
- 기존 요청 수/순서를 변경하는 자동 페이지 보충은 추가하지 않았다. 버튼은 한 페이지씩 기존 함수를 호출한다.
- 핵심 변경은 70줄로 200줄 이내이며 새 의존성은 없다. BE 준비 완료 후 릴리스한다. 되돌릴 때 DB나 ISBN은 수정하지 않는다.

## 5. 측정 방법

Node 내장 test와 TypeScript transpile로 실제 응답 변환/JSX 조건/페이지 계산을 실행했다. 네트워크는 모의 응답으로 대체했다. 코드 타입 검사 및 대상 파일 ESLint를 실행했다. 네이티브/브라우저 전체 렌더링 E2E를 수행한 것은 아니다.

## 6. 측정 결과

- `node --test scripts/yes24-client.test.mjs`: 5개 통과.
- npm run typecheck, check:typography, check:spacing 통과. 대상 ESLint 오류 0, 기존 경고 5개.
- 상품번호를 ISBN으로 넣지 않는 경로, 빈 페이지→다음 페이지, 링크 null 및 신규/기존 이미지 계약을 관련 테스트로 확인했다.
- 렌더 성능·실제 기기·운영 API 연결은 측정하지 않았다.

## 7. 가설 판단과 결론

기존 응답 필드를 활용해 예스24로 전환할 때 막히는 클라이언트 경로를 수정했다. 제한 없이 페이지를 자동 수집하는 구현은 추가하지 않았다. 데이터 연결을 변경하지 않고 타입과 회귀 검증을 통과했다. 실제 사용자 화면 검증은 후속 항목으로 남는다.

### 후속 직접 검증

예스24 백엔드가 준비된 테스트 환경에서 추천 링크, 두 공급자의 표지, 상세 링크/null, 빈 검색 페이지 다음 버튼, 모임·책이야기 도서 선택·좋아요를 확인한다. RN은 EXPO_PUBLIC_YES24_RANKING_URL을 공개 링크 재정의에만 사용하며 API 키를 넣지 않는다. 서버 전환 전 배포하지 않는다.
