### 범위와 사용자 동작 계약

- 로그인하지 않았으면 `내 소식` 목록을 비우고 API를 호출하지 않는다.

## 2. 변경 전

`loadMyNews()`가 이미 존재하는 공통 커서 페이지 수집 로직을 화면 안에서 다시 구현하고 있었다.

```ts
const allItems: RemoteNewsSummary[] = [];
let cursorId: number | undefined;
const visitedCursors = new Set<number>();
const seenNewsIds = new Set<number>();

for (let i = 0; i < 100; i += 1) {
  const response = await fetchMyNewsList(cursorId);
  response.items.forEach((item) => {
    if (seenNewsIds.has(item.id)) return;
    seenNewsIds.add(item.id);
    allItems.push(item);
  });
  if (!response.hasNext || typeof response.nextCursor !== 'number') break;
  if (visitedCursors.has(response.nextCursor)) break;

  visitedCursors.add(response.nextCursor);
  cursorId = response.nextCursor;
}
```

## 3. 가설·근거·기대 결과

### 가설

화면의 중복 루프를 기존 `collectAllCursorPages()` 호출로 바꾸면, 같은 규칙의 구현·변경 지점이
2곳에서 1곳으로 줄고 화면 내부 수집 코드는 18줄에서 4줄로 줄어든다. 공통 유틸의 기본값과
처리 순서가 기존 코드와 같으므로 사용자 동작은 그대로 유지될 것이다.

### 근거

- 두 구현 모두 기본 최대 페이지 수가 100이다.
- 두 구현 모두 `item.id`로 중복을 제거하며 첫 항목과 입력 순서를 유지한다.
- 두 구현 모두 `hasNext`, 숫자형 `nextCursor`, 반복 커서를 같은 순서로 검사한다.
- 공통 유틸은 페이지 요청 오류를 그대로 전파하므로 화면의 기존 `catch`가 계속 처리한다.
- `loadMyNews()`의 로그인, 매핑, 오류, 토스트와 로딩 코드는 수집 블록 밖에 있어 수정할 필요가 없다.
