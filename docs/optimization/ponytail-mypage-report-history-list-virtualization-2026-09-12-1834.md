## 2. 변경 전

신고 API의 모든 커서 페이지를 수집한 뒤 `ScrollView` 안에서 전체 카드를 `map()`으로 즉시 만들었다.
신고 내역이 많아지면 화면 밖 카드까지 첫 렌더 작업에 포함됐다.

```tsx
<ScrollView contentContainerStyle={styles.settingsContent}>
  <View style={styles.reportList}>
    {reportHistory.map((report) => (
      <Pressable
        key={report.id}
        onPress={() => handlePressReportHistory(report)}
      >
        {/* 신고 유형, 대상, 날짜, 내용 */}
      </Pressable>
    ))}
  </View>
</ScrollView>
```

## 3. 가설·근거·기대 결과

### 가설

신고 내역 화면만 React Native 기본 `FlatList`로 바꾸면 화면 주변 카드부터 렌더링하므로 19·100·500개
조건에서 첫 커밋 시간과 초기 카드 생성 수가 감소하고, 기존 사용자 동작 계약은 유지될 것이다.

### 근거

- `fetchMyReports()`는 `collectAllCursorPages()`로 최대 100페이지를 수집할 수 있다.
- 기존 `ScrollView + map()`은 수집한 모든 신고 카드를 한 번에 React 요소로 만든다.
- 같은 화면의 팔로우와 내 소식 목록이 이미 별도 `FlatList` 패턴을 사용한다.
- 데이터 수집·오류 처리·화면 이동은 신고 카드의 렌더 컨테이너와 분리되어 있다.
- 새 라이브러리 없이 React Native의 기존 `FlatList`만 사용한다.

## 4. 변경 후

신고 카드 JSX를 `renderReportHistoryItem()`으로 옮기고 신고 관리 화면에만 `FlatList`를 사용했다.
헤더와 상태 렌더러는 기존 문구와 표시 순서를 그대로 전달한다.

```tsx
<FlatList
  data={reportHistory}
  keyExtractor={(report) => report.id}
  renderItem={renderReportHistoryItem}
  ItemSeparatorComponent={() => <View style={styles.reportListSeparator} />}
  ListHeaderComponent={renderReportHistoryHeader()}
/>
```

```tsx
const renderReportHistoryItem = ({ item: report }) => (
  <Pressable onPress={() => handlePressReportHistory(report)}>

  </Pressable>
);
```

### 근거

- `reportHistory.map()`은 1곳에서 0곳, 신고 내역 `FlatList`는 0곳에서 1곳이 됐다.
- 기존 배열·ID·순서·카드 필드·대상 이동·로딩·빈 결과·오류·로그인 조건을 유지했다.

### 결론

최대 100페이지까지 수집 가능한 신고 내역을 `ScrollView + map()`으로 한 번에 렌더하던 구조를 화면 전용
`FlatList`로 바꿨다. 500개에서 첫 커밋 카드가 500개에서 10개로 줄고 중앙값은 160.49ms에서
6.50ms로 95.9% 감소했다. 작은 7개 목록은 중앙값이 35.0% 증가했고 동일 거리 스크롤 FPS도 개선되지
않아 전체 판정은 부분 확인이다. 따라서 이 변경은 신고 내역이 누적될 때의 초기 렌더 비용을 줄이는
최적화로 설명하며, 모든 목록 크기와 스크롤 성능을 개선했다고 일반화하지 않는다.
