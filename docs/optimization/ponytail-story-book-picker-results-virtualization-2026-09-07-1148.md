## 2. 변경 전

도서 선택 모달의 검색 결과를 `ScrollView` 안에서 `map()`으로 모두 만들었다. 다음 페이지 결과가
누적되면 화면 밖 카드까지 즉시 렌더 트리에 포함됐다.

```tsx
<ScrollView onScroll={handleBookSearchScroll}>
  {bookSearchSearched && !bookSearchLoading && bookSearchResults.length === 0
    ? <Text>검색 결과가 없습니다.</Text>
    : null}

  {bookSearchResults.map((bookItem, index) => (
    <Pressable
      key={`${bookItem.isbn}-${index}`}
      onPress={() => handleSelectBookFromSearch(bookItem)}
    >
      {/* 표지, 제목, 저자, 설명 */}
    </Pressable>
  ))}

  {/* 추가 로딩·마지막 결과 */}
</ScrollView>
```

## 3. 가설·근거·기대 결과

### 가설

검색 결과의 `ScrollView + map()`을 이미 사용 중인 React Native `FlatList`로 바꾸면 화면 주변 카드부터
생성해 긴 결과의 첫 커밋 시간, 초기 카드 생성 수와 최악 프레임 간격이 감소한다. 기존 배열, 키,
카드 UI, 하단 240px 조회 조건과 선택 핸들러를 그대로 전달하면 사용자 동작은 유지될 것이다.

### 근거

- 결과는 페이지가 추가될 때마다 `bookSearchResults`에 누적된다.
- 기존 `map()`은 누적 카드 전체를 즉시 React 자식으로 만들었다.
- `FlatList`는 이 화면에 이미 import돼 있어 새 패키지나 네이티브 설정이 필요 없다.
- 검색과 페이지 병합은 `useBookSearch()`에, 책 선택 반영은 `handleSelectBookFromSearch()`에 분리돼 있다.

### 기대 결과와 성공 기준

| 지표 | 기준값 | 목표값 | 성공 조건 |
| --- | ---: | ---: | --- |
| 전체 결과 즉시 생성 코드 | 1곳 | 0곳 | `bookSearchResults.map()` 제거 |
| 100·500개 250ms 카드 생성 | N개 | N개 미만 | 화면 주변 카드만 생성 |
| 19·100·500개 첫 커밋 중앙값 | 변경 전 | 감소 | 같은 Release 조건 30회 비교 |
| 결과 ID·개수·순서 | 기존 배열 | 동일 | 같은 배열과 키 사용 |
| API·선택 로직 변경 | 0곳 | 0곳 | 대상 로직 diff 없음 |

작은 목록은 `FlatList` 고정비가 더 클 수 있어 목록 크기별로 나눠 판정한다.

## 7. 가설 판단과 결론

### 판정

`부분 확인`

### 근거

- 전체 카드를 즉시 만드는 `bookSearchResults.map()`이 1곳에서 0곳으로 줄고 `FlatList`가 1곳 생겼다.
- 기존 배열, 키, 카드 문구·순서와 `handleSelectBookFromSearch()`를 그대로 연결했다.
- 검색 API, 캐시, 페이지 병합·중복 제거와 하단 240px 추가 조회 코드는 수정하지 않았다.
- 19·100·500개에서 첫 커밋 중앙값이 각각 23.1%, 78.3%, 94.6% 줄었다.
- 100·500개에서 카드 생성이 40개로 제한되고 최대 프레임 간격 p95도 42.4%, 82.2% 줄었다.
- 7개에서는 첫 커밋 중앙값이 3.06ms에서 3.17ms로 3.3% 늘어 작은 목록의 고정비가 확인됐다.

### 결론

책이야기 작성의 도서 선택 결과를 React Native 기본 `FlatList`로 바꿔 누적된 카드 전체를 즉시
생성하는 구조를 제거했다. 데이터·API·표시 순서·문구·책 선택과 작성 화면 복귀는 유지했고 핵심
변경은 48줄로 200줄 예산의 24%이며 새 의존성은 없다. Release 실험에서 19개부터 첫 커밋이 23.1%
단축됐고 100·500개에서는 각각 78.3%, 94.6% 단축됐다. 7개에서는 3.3% 느려 가설은 목록 규모에
따라 부분 확인됐으며, 결과는 네트워크와 이미지 비용을 제외한 렌더러 마이크로 벤치마크로 한정한다.

### 후속 작업

실제 여러 페이지 결과를 불러올 수 있는 기기에서 검색 입력부터 선택 완료까지 30회 측정하면 API와
원격 표지를 포함한 체감 성능 자료를 보완할 수 있다.
